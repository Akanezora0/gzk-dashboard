# 多端协作与验收

## 1. 日常分支与PR

用户2026-11-05明确约定：今后Codex对Dashboard的修改均先在`codex/<任务>`分支实施，验证后再合并到main；本次分支为`codex/compact-shared-masthead`。保持任务提交与合并记录，禁止直接在main修改或强推。

每人独立clone；开始新任务前更新main。不要共享工作目录或直接覆盖别人分支。例：

```bash
git switch main
git pull --ff-only
git switch -c codex/short-task-name
# 修改并验证
npm run verify:snapshot
npm test
npm run build
git add <本次文件>
git commit -m "说明具体改动"
git push -u origin codex/short-task-name
```

向main提PR，描述触发场景、结果、测试和截图。只改UI的PR不要携带整套重导数据；数据更新PR需列来源、版本、数量变化及受影响页面。合并冲突按模块/口径核对，不直接“全部采用我的版本”。main禁止强推。提交与推送仍按各次用户授权执行。

2026-11-05完整协作版保留旧main与claude/research-strength-v2历史。PR #1研究力量设计已在服务器审定使用，不能再按初始README“未审定”处理。

## 2. 给AI的任务说明建议

提供目标页面URL、要改的具体行为、截图/参考、允许改动范围、不能改的数值与布局、验收动作。要求先读AGENTS与相关docs，不让工具重新猜测项目背景。

推荐交接顺序：项目主线 → 有效数据版本 → 页面组件 → 需求 → 截图验证。涉及数字时给出数据来源和计算口径；设计参考不自动成为新的事实来源。

## 3. 验收

自动检查：快照SHA/行数/文件完整、接口响应可读、所有综述、候选首末页与搜索、低空贡献筛选、前后端构建。GitHub Actions在push main和PR运行这些检查，只验证，不部署。

页面修改追加检查：

- 1440、1920宽屏及390窄屏；同级页面同一套卡片/标签/数值动画，不增加横向滚动或文字裁切。
- 数据总览3视图、AI9类数据、低空资料、两领域技术树与综述；正文引用/参考文献搜索/关闭恢复。
- AI原始证据链6种关系、投入/成果/70点/曲线、研究力量2视图和案例下钻；保留旧路由深链。
- 年度动画默认末年，点击播放才开始；暂停保持、到末年停止。统计数值650ms动画与独立年份播放器规则区分。
- 弹层Esc关闭、点击遮罩关闭、滚动锁恢复、焦点恢复；悬浮提示不越界。
- 控制台错误、请求失败、下载链接、搜索无匹配状态。

截图存PR附件即可，不把多轮调试截图和浏览器缓存永久塞入仓库。数值/总量一致不代表因果结论成立，研究解释仍按03与原文证据审查。

## 4. 安全与版本

`.env`、密钥、原始DB、模型、备份和node_modules已忽略。提交前检查git diff与untracked，不使用git add -f绕过。snapshot只收录已授权展示范围；新增敏感资料需确认共享范围。

SOURCE_MAP记录原服务器源码SHA；snapshot/api/index.json记录URL、状态、内容SHA与导出时间，records/manifest记录每个来源分片的行数和SHA。发布说明应同时写代码commit与数据snapshot版本，便于回退与多人讨论。
