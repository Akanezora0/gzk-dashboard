## 2. API契约

- `/api/llm/bootstrap`：主页、库存、技术树、时间线、综述索引。
- `/api/llm/analytics?namespace=...&scope=ai`：每来源统计；保留ai/llm/context现有快照。
- `/api/llm/records?namespace=...&scope=ai&q=...&offset=0&limit=10`：标题包含搜索、分页、证据详情。只对ASCII英文字母不区分大小写；`%`、`_`按字面搜索；排序为原year DESC,uid ASC。offset0–300000、limit1–50、q最长100。scope=ai是现有页面范围；其他范围转live，不返回假空成功。
- `/api/llm/chain-summary?scope=ai`、`/api/llm/graph?chain=...&scope=ai&limit=20`：当前六种关系图。快照包含5/10/20/30/40/50/60样本量，当前页面固定20；新增任意样本量需补相应接口实现。
- `/api/llm/survey/{topic_id}/{A|B}`：完整正文、引文、参考文献。
- `/api/low-altitude/overview`、`tech/tree`、`tech/{id}`：低空总览和33技术详情。
- `/api/low-altitude/survey?tech_tag_id=...&line_type=A|B`：66篇低空综述。
- `/api/low-altitude/chain?chain_type=...&limit=...&aggregate=...`：当前7组关系视图。
- `/api/low-altitude/contribution`：用包内3727行投影动态按技术/层级/年份计算，保持原评分和舍入。

参数顺序不影响命中；未知接口/组合返回明确404。发布失败的既有综述保留原状态。GET/HEAD可用，写入请求405。详情中的来源文件路径移除了本机绝对目录前缀，仍保留相对来源与行号，浏览器不直接访问原始资料盘。

## 3. 更新方式

优先在原项目完成数据验收和生产，再更新本仓库快照。展示数据不是独立研究事实的第二份维护源。

1. 明确更新范围、来源版本、口径和受影响路由。
2. 用原后端读接口刷新相应响应，或由对应生产脚本生成analysis_public。全量记录投影需从候选源导出，保持UID和排序，不只保存第一页。
3. 更新api索引SHA、records清单和总manifest版本；静态文件与数据保持同批。原始模型/数据库不随快照上传。
4. `npm run verify:snapshot` + `npm test` + build；在独立目录对照原服务器总量、搜索、首末页及几个筛选组合。
5. 单独数据PR说明差异；用户确认发布后才同步线上配置。

API响应可使用以下只读工具导出至全新临时目录（需Python3）：

```bash
python scripts/refresh_api_snapshot.py --base http://localhost:5174 --output /tmp/api-next
# 原项目服务器专用：读取正式候选库，导出新的展示投影
python scripts/server/export_record_projection.py --project-root /path/to/gzk_jc --output /tmp/records-next
```

工具不自动覆盖仓库；先对照质量与版本再替换对应目录。API工具按当前索引请求，新增技术点或接口需明确扩充索引；静态资产与低空贡献投影需要相应生产流程另行更新。

手工更新动态只修改web/content/catalog-activity.json，不需要刷新API快照。研究事件策展内容和指标数值需按05规定从各自生产入口维护。

## 4. 本次保留的现状与后续事项

- 部分低空“基金贡献度”下拉类别文本与后端tech_layer值不完全相同（后端有“层”等后缀），选择后可能为0。协作版保持与线上完全相同，后续作为单独口径/筛选修复任务，不能在迁移时无说明改统计结果。
- 技术版图若干公开事件未填写出处URL；展示迁移保留现状，事实补核与界面调整分开提交。
- 案例专题入口尚在筹备，首页汇总、领域检索和研究力量内的具体案例不受此影响。
- 原服务器全文库、向量检索、模型调用和多智能体运行未复制到前端仓库；需要扩展新研究时由原项目提供新的验收后接口/产物。
