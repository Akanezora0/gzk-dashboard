# 本地运行与服务器部署

## 1. 安装与开发

推荐 Node.js 22 LTS，最低20.19。根目录是 npm workspaces；只在根目录执行 `npm ci`，不用分别在 web/lowalt 安装。不需要 Python、数据库、API key 或内网连接。

```bash
npm ci
npm run dev
```

默认 http://localhost:5184/overview。predev 自动构建低空嵌入应用；AI 主站修改后热更新。低空或它复用的 legacy/shared 代码改动后执行 `npm run build:lowalt`，刷新页面。完整构建 `npm run build`，预览 `npm run preview`。本地 API 由 Vite 中间件提供，因此不能直接双击 build/index.html，也不能仅把静态目录丢到没有API的文件服务器上。

`.runtime/` 保存缓存和构建结果，可重建，不纳入 Git。两个应用都能在路径含空格的目录运行；不要硬编码原服务器绝对路径。

## 2. 配置

将 `.env.example` 复制成 `.env.local`。配置读取顺序：进程环境 > .env.local > .env > 默认值；配置变化后重启服务。

| 变量 | 默认 | 用途 |
|---|---|---|
| DASHBOARD_MODE | snapshot | 本地展示快照；live连接原接口 |
| DASHBOARD_PORT | 5184 | 前端端口，冲突时换5185等 |
| DASHBOARD_HOST | 127.0.0.1 | 本地访问；团队测试可按需设0.0.0.0 |
| DASHBOARD_RUNTIME | .runtime | 构建/缓存位置 |
| DASHBOARD_API_BASE | http://127.0.0.1:5174 | live模式只读API入口 |
| DASHBOARD_LIVE_ASSETS | 空 | live可选展示目录，含analysis_public/与reference_serving/ |

只配置live API而不配置LIVE_ASSETS时，图表静态资料仍用仓库快照。若要看服务器最新值，两者需来自同一发布版本。密钥不需要写在前端环境中。接口中间件拒绝POST等写入方法。

## 3. 服务器集成

仓库与原项目并非同根目录。`web/`等对应服务器 `dashboard/cursor_ui/web/`；SOURCE_MAP记录发布时源文件SHA。此次portable迁移改动构建配置，不改变在线运行实例。

部署由有权限人员完成：

1. 对本次文件、展示产物建立 verified 备份，遵守原项目 formal_writer 锁和 checkpoint/seal/恢复预检流程。
2. 比较已验收基线至PR的真实diff，仅合入本次改动。**保留服务器自己的env、代理、端口和artifact路径。** 不把整个独立仓库覆盖原项目目录。
3. 若只改UI，构建即可；若涉及研究数据，先在原项目通过 `python manage.py run dashboard/cursor_ui/scripts/build_ai_chain.py` 等对应脚本生成。断言失败时停下核查，不改断言凑数。
4. 确认既有data目录、综述和投产数据不被snapshot反向覆盖。重建两个应用，按服务器当前服务方式发布；重启哪个服务以实际进程/服务配置为准，仓库不臆造systemd名字。
5. 用已审定路由和宽度验收，记录commit、数据版本、备份与结果；seal并做恢复预检。

原服务器使用完整项目后端：AI接口5174，低空接口由其只读代理转发；本地snapshot无需这些服务。研究分析脚本的全库计算不属于前端部署必跑步骤。

## 4. 常见情况

- 端口占用：设置DASHBOARD_PORT；不要终止不属于本任务的进程。
- 低空空白或404：运行build:lowalt，查控制台和本地构建目录。
- API 404：检查query是否已收录；不能用空数组兜底冒充成功。现有页面组合已包含，新增接口需扩展快照/实现。
- 搜索数量与首页不一致：检索是当前候选展示集合，首页是规范库汇总，口径见03。
- 初次某个来源搜索稍慢：本地按来源解压gzip记录；只保留一类缓存，避免把全库读入内存。后续同来源翻页不重复解压。
- 更新活动更改后看不到：改web/content/catalog-activity.json；正式build需重建，开发模式刷新即可。
